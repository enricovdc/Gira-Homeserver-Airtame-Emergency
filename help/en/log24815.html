1. Description

Triggers and clears Airtame Emergency Alerts from a KNX / Gira event. A rising edge on input Trigger sends an Initiated message to the Airtame Cloud public emergency-alerts endpoint; a rising edge on Clear sends a Resolved message that references the active alert.
Both Airtame payload formats are supported, selectable per instance via the Payload format input:
  • json — Airtame Option 2 (recommended in the docs), Content-Type: application/json.
  • cap — Airtame Option 1 (CAP 1.2 XML), Content-Type: application/xml, strictly validated against the CAP XSD.
The module authenticates via HTTP Basic with the configured API key, retries on 429 / 5xx / timeouts with exponential backoff, and uses the remanent store to survive HomeServer restarts mid-alert.
Important
The endpoint must be HTTPS. The module refuses to send to an http:// URL and reports config: endpoint must use HTTPS on Last message instead. The API key is sent as the password of an HTTP Basic header — treat it as a secret and never log it in plaintext.
Note
For CAP, Airtame uses <urgency> to choose between high / medium / low templates — the SRP templates (secure, lockdown, evacuate, shelter, hold, all-clear, blank) are reachable only via JSON. Drills (Is drill = 1) use the JSON isDrill: true flag; CAP has no equivalent so drills in CAP are sent with <severity>Minor</severity> but appear without the Drill badge.

5. Payload formats & AlertTemplate values

Both formats POST to the same endpoint with the same Basic auth header; only the Content-Type and body differ.
JSON (Option 2) — Content-Type: application/json:
fieldrequirednotes
id yesunique per alert; same id resolves the alert.
status yesInitiated | Resolved
template yessee table below
headline yestitle shown on screen
description nobody text shown on screen
isDrill noboolean; shows Drill badge
expiresAt noISO 8601 with timezone
CAP 1.2 XML (Option 1) — Content-Type: application/xml, namespace urn:oasis:names:tc:emergency:cap:1.2. Cancel uses <msgType>Cancel</msgType> + <references>sender,identifier,sent</references> pointing at the original. Airtame derives the template from <urgency>:
Template inputCAP <urgency>Airtame routes to
high, lockdown, evacuate, shelter, secureImmediatehigh
medium, hold Expected medium
low, all-clear, blank Future low
Choosing a format
Use json unless your environment specifically requires CAP. SRP templates (lockdown, evacuate, shelter, secure, hold, all-clear, blank) are only reachable via JSON because CAP routes the template through <urgency> only.
