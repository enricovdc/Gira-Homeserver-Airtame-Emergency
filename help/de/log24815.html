1. Beschreibung

Löst Airtame Emergency Alerts aus einem KNX-/Gira-Ereignis aus und hebt sie wieder auf. Eine steigende Flanke am Eingang Auslöser sendet eine Initiated-Nachricht an den öffentlichen Emergency-Alerts-Endpunkt von Airtame Cloud; eine steigende Flanke am Eingang Aufheben sendet eine Resolved-Nachricht, die auf den aktiven Alarm verweist.
Beide Airtame-Payload-Formate werden unterstützt und sind pro Instanz über den Eingang Payload-Format wählbar:
  • json — Airtame Option 2 (in der Doku empfohlen), Content-Type: application/json.
  • cap — Airtame Option 1 (CAP 1.2 XML), Content-Type: application/xml, strikt gegen das CAP-XSD validiert.
Authentifizierung erfolgt per HTTP-Basic mit dem konfigurierten API-Schlüssel. Bei 429 / 5xx / Timeouts wird mit exponentiellem Backoff wiederholt. Der Remanentspeicher trägt den aktiven Alarm über einen HomeServer-Neustart hinweg.
Achtung
Der Endpunkt muss HTTPS sein. Der Baustein verweigert http://-URLs und meldet stattdessen config: endpoint must use HTTPS auf Letzte Meldung. Der API-Schlüssel wird als Passwort eines HTTP-Basic-Headers gesendet — entsprechend geheim halten und niemals im Klartext protokollieren.
Hinweis
Für CAP wählt Airtame die Vorlage (high / medium / low) ausschließlich aus <urgency>. Die SRP-Vorlagen (secure, lockdown, evacuate, shelter, hold, all-clear, blank) sind nur über JSON erreichbar. Übungen (Übung = 1) verwenden in JSON das Flag isDrill: true; CAP kennt kein Äquivalent, daher werden Übungen in CAP mit <severity>Minor</severity> versendet, das „Drill“-Abzeichen erscheint dann jedoch nicht.

5. Payload-Formate & AlertTemplate-Werte

Beide Formate sprechen denselben Endpunkt mit derselben Basic-Auth-Header an — nur Content-Type und Body unterscheiden sich.
JSON (Option 2) — Content-Type: application/json:
FeldPflichtHinweis
id jaeindeutig pro Alarm; gleiche ID hebt den Alarm auf.
status jaInitiated | Resolved
template jasiehe Tabelle unten
headline jaTitel auf dem Bildschirm
description neinTextkörper auf dem Bildschirm
isDrill neinBoolean; zeigt Drill-Abzeichen
expiresAt neinISO 8601 mit Zeitzone
CAP 1.2 XML (Option 1) — Content-Type: application/xml, Namespace urn:oasis:names:tc:emergency:cap:1.2. Cancel verwendet <msgType>Cancel</msgType> + <references>sender,identifier,sent</references> mit Verweis auf den Original-Alarm. Airtame leitet die Vorlage aus <urgency> ab:
Eingang „Vorlage“CAP <urgency>Airtame wählt
high, lockdown, evacuate, shelter, secureImmediatehigh
medium, hold Expected medium
low, all-clear, blank Future low
Format wählen
Standardmäßig json verwenden, außer die Umgebung verlangt explizit CAP. SRP-Vorlagen (lockdown, evacuate, shelter, secure, hold, all-clear, blank) sind nur per JSON erreichbar, weil CAP die Vorlage ausschließlich über <urgency> auswählt.
